# Asset Doctor 2.0.1 — верхние инструменты и безопасные операции с суставами

Дата: 2026-10-14, Europe/Riga. Основа — вручную принятый `d09a8d4` (2.0.0). Windows/Tauri Desktop; отдельный веб-продукт EOL. После этого прохода работа останавливается для ручной приёмки.

## Изменения

- Инструменты скелета находятся сверху во viewport. Выбор / Перемещение / Поворот XYZ / Ось кости — четыре отдельные кнопки. Числовые координаты, поворот и длина открываются в раскрываемом блоке выбранного сустава, чтобы сохранять место для модели. Справа остаются имя, длительность и список анимаций, история и проверка GLB.
- Верхний дубликат выбора пола удалён. Сохранено основное меню в правом верхнем углу viewport со всеми прежними поверхностями.
- Синий — просмотр и информация; зелёный — изменения и сохранение; красный — отмена, удаление и предупреждения; фиолетовый — вспомогательные действия. Состояния различаются также подписями, значками и aria-pressed.
- Add создаёт настоящий дочерний Bone, добавляет его в конец каждого skin, содержащего выбранного родителя, и сохраняет его в GLB. Существующие веса и joint slots не меняются. Новый сустав имеет уникальное имя `Joint_N` и **не получает веса вершин**: редактор весов не входит в этот проход.
- Delete удаляет сустав из активного графа и skins, пересчитывает JOINTS_0 и сохраняет WEIGHTS_0. Undo/Redo/reset восстанавливают тот же объект/UUID, порядок детей и skin joints, IBM и геометрию.
- ПКМ по видимому суставу или кости открывает Add/Delete; Escape и щелчок вне меню закрывают его. Перетаскивание ПКМ сохраняет панорамирование камеры. Ctrl+Z и принятые Gizmo/clip controls сохранены.
- Версия в шапке, Cargo и Windows-файлах — 2.0.1. Дизайн иконки не изменён.

## Контракт безопасного удаления

Разрешён только конечный сустав без дочерних костей/вложений, положительных весов и анимационных дорожек. Корневые суставы, skin.skeleton и последний joint запрещены. Проверяются и исходные animation channels, чтобы пропущенная загрузчиком дорожка не разрешила удаление. Некорректные/нечитаемые исходные веса блокируют удаление исходного сустава: нормализация импортёром не является доказательством отсутствия исходного влияния.

Сжатые skin attributes, дополнительные наборы influences и конфликтующие порядки joints у общего меша блокируются с причиной. Исходный UBYTE/USHORT тип JOINTS сохранён в экспортном accessor. Delete выполняется в Hybrid и без активных Repair reports; после изменения JOINTS следует Save → Reimport перед следующим Repair. Добавление не требует изменения геометрии и совместимо с ранее разрешёнными combined repairs.

При удалении исходного сустава его неизменённая запись в массиве исходных JSON nodes остаётся **неиспользуемой**, чтобы не перенумеровывать потенциальные ссылки в неизвестных расширениях/extras. Узел не входит в сцену или skin и не появляется в активном скелете после повторного импорта. Диагностика исходного документа может сообщить о недостижимой записи. Это сохранение исходных данных, а не скрытый деформирующий joint. Обычный Repair-only exporter сохраняет прежний строгий контракт по недостижимым source nodes.

## Сохранность и проверки

Новые экспортные identities хранятся отдельно от read-only importer associations и userData. Source GLB patch добавляет только явно разрешённые nodes/children/skin joints/IBM/JOINTS. Оригинальный binary prefix и остальные JSON-поля, материалы, текстуры, extras и sampler данные сверяются; runtime metadata в extras не добавляется.

Структурный verifier использует настоящий свежий импорт, проверяет canonical identities, родителей, TRS, порядок joints, IBM, attributes и клипы. Деформация проверяется для каждой вершины в Rest и шести фазах каждого клипа: 0 / 0.13 / 0.33 / 0.61 / 0.87 / 1. Повреждённые добавленные nodes, children, skin order и JOINTS дают REGRESSION.

В ходе проверки устранены две зависимости: обычное восстановление Rest не должно возвращать старую Heal/Smooth geometry; структурная история должна восстанавливать только собственный JOINTS delta и атомарно отклонять конфликт с последующим Repair. Есть регрессии Delete → Undo → внешний Heal → Restore/Rename/Undo, конфликтующего Redo, двух последовательных удалений и Smooth → Undo/Redo → Export. Также покрыто исчезновение минимального положительного Float32 веса при нормализации.

Окончательные результаты проверок и измерения находятся в `BUILD_INFO.txt` и `evidence/` поставляемой сборки. Предыдущие ограничения verified rig export из QA_ANIMATION_RIG_EXTENSION.md остаются действующими. Pose Preview — временная проверка; редактора анимационных ключей в этом патче нет.

## Ручная приёмка владельцем

1. Запустить 2.0.1. Проверить верхнюю панель и четыре кнопки, раскрытие координат, свободное место для анимаций справа и цвета. Изменить размер окна; проверить единственное меню пола и все его поверхности.
2. На своей модели проверить выбор близких суставов, перемещение, XYZ/Ось кости, Follow/Hold и Ctrl+Z вне поля ввода. В поле Ctrl+Z должен отменять текст. Переименование/длительность клипа и Turntable работают как в принятой 2.0.0.
3. В режиме «Редактировать» выбрать родительский сустав → Добавить. Новый `Joint_N` должен появиться в иерархии и X-Ray; его можно переместить/повернуть. Базовая форма меша не меняется, поскольку новый сустав не имеет весов. Undo/Redo восстанавливают его.
4. Проверить ПКМ: Add/Delete, Escape, щелчок вне меню и перетаскивание ПКМ для панорамы. У исходного взвешенного/анимированного сустава Delete заблокирован с причиной. Новый конечный сустав без весов можно удалить и вернуть Ctrl+Z.
5. Verify Edited GLB → Save под новым именем → Reimport. Проверить число и положения суставов, имена/длительности клипов, проигрывание, материалы и текстуры. Для удаления исходного безопасного leaf приложен тестовый GLB и экспортный пример в evidence; сохранённый orphan source record описан выше.

Новый EXE автоматически не запускается; установщик автоматически не применяется. Headless проверки общего desktop frontend и сборка не заменяют ручную проверку нативного Windows-окна. ПК остаётся у владельца. После этой приёмки следующий согласованный этап — отдельный PASS 7 Rig Fitting; он здесь не начат.
