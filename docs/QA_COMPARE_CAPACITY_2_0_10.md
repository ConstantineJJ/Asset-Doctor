# Compare: отказ на седьмой/восьмой модели — 2.0.10

15 октября 2026. Исправление замечания приёмки 2.0.9; F08 не выполняется.

## Причина

В 2.0.9 был введён общий предел исходников Compare 128 MiB при восьми местах и 64 MiB на файл. Это несогласованные продуктовые ограничения. Отказ не свидетельствовал о фактическом исчерпании памяти Windows. Общий текст также ошибочно предлагал уменьшать число Compare моделей при превышении других, независимых бюджетов.

Из предоставленной владельцем папки `D:/Desktop/Бурундуки/GLB` выбраны два набора. Порядок в тесте приближён к скриншотам: точный порядок исходной ручной сессии неизвестен.

| Набор | Перед отказом | После добавления | Итог восьми |
|---|---:|---:|---:|
| Порог на седьмой | 128 958 828 bytes (6 моделей) | 141 975 804 bytes (7 моделей) | 158 115 792 bytes |
| Порог на восьмой | 128 257 268 bytes (7 моделей) | 158 115 792 bytes (8 моделей) | 158 115 792 bytes |

Все семь разных файлов имеют размер 13 016 976–29 858 524 bytes, ниже 64 MiB. Одна модель повторяется в двух местах, как допускает Compare. Сумма должна учитывать оба удерживаемых исходника.

## Изменение

Compare сохраняет максимум восемь моделей. Общий предел исходников выводится из числа мест и допуска на один файл: **8 × 64 MiB = 512 MiB**. Это верхняя граница named source buffers, а не обещание потребления RAM или автоматическая оценка возможностей устройства. Неизменны последовательный импорт, проверка native stat до чтения, отбрасывание лишних путей до I/O, per-file/worker/packet/history guards и сохранение прежней модели/Undo при отказе.

Ошибка размера файла или суммы исходников Compare называет проверяемые данные, запрошенный размер и установленный максимум. Общий текст остальных отказов также показывает размеры и больше не выдаёт рекомендацию о Compare для любой операции.

## Проверка

Автоматический regression использует два набора валидных GLB с размерами исходников из таблицы; лишнее BIN-хранилище позволяет отдельно проверить source admission без зависимости от декодированных текстур. Дополнительный запуск того же теста с `ASSET_DOCTOR_PRIVATE_COMPARE_DIR` использует реальные файлы владельца с диска. Эти файлы не редактируются и не входят в комплект; SHA256 сравнивается до/после.

Проверяются восемь загруженных моделей, отсутствие отказа, переход Grid → Lineup и удаление всех восьми, отсутствие page errors. Память измеряется только у процессов собственного headless Edge с интервалом 100 ms. Это не native WebView2 peak/VRAM certification. Синтетический тест source bytes не доказывает работу восьми произвольных текстурированных файлов по 64 MiB.

Результаты:

- До исправления оба browser regression завершились отказом: 6/8 и 7/8; unit gate показал несогласованность 134 217 728 против 536 870 912 bytes. Исторический RED сохранён.
- TypeScript **PASS**; unit/integration **333/333 PASS**, включая native metadata admission восьмой модели и сохранение ограничений worker/packet/Undo.
- Свежая production regression **93/93 PASS**, **207.55 с**, без skipped/flaky/unexpected, 53 приложения доказательств. Для Repair/Undo/Export/Fitting на 500 001 triangles не зарегистрированы long tasks ≥50 ms; gate ≤100 ms сохранён.
- Дополнительно production запуск на частных GLB владельца **2/2 PASS**, **18.90 с**, четыре приложения доказательств. Все восемь реально декодированы и отображены, затем удалены. Ошибок страницы нет, SHA256 исходников до/после совпадают. Ручная исходная последовательность кликов этим не воспроизводится буквально; проверяются два явно заданных порядка с теми же порогами.
- Для наборов с текстурами sampled private peaks собственного production headless Edge: **10 878.23 MiB** и **11 207.85 MiB** (56 и 48 samples). До этого development повтор дал 11 927.39 и 11 453.60 MiB. Это разные прогоны, не доказательство улучшения памяти. Высокая стоимость decoded текстур подтверждает, что 512 MiB источников нельзя трактовать как 512 MiB RAM. Нативный WebView2 и восемь произвольных файлов по 64 MiB этим не сертифицированы.
- Windows release/NSIS **PASS**. EXE ProductVersion/FileVersion **2.0.10**, **11 385 344 bytes**, SHA256 `517934A5783801CF1A0881D911B0D9A2B538FD6C0E8878D8F01F081FD9DB65BE`. NSIS SHA256 `243691C9F7988950451434D317F5A0C5034AF00F1A7CAEC77A1684DF7D87475A`. EXE и installer автоматически не запускались.

Прежний перенос общей Compare toolbar в узком окне остаётся виден на приложенных снимках; компоновка toolbar не менялась в этом исправлении. Доступность удаления карточек проверена отдельно.

Приёмка 2.0.9 выявила регрессию; исправление 2.0.10 технически проверено, **F07 остаётся открытым до повторной Windows приёмки**. Принятые владельцем исправления 2.0.8 и прежние неизменяемые комплекты сохраняются. F08/F09 не выполнялись.
