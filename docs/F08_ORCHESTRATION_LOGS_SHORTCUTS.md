# F08 и пользовательские инструменты

15 октября 2026. Владелец закрыл F07 после приёмки 2.0.10 и разрешил F08, новые тайлы, назначаемые горячие клавиши, системный журнал и отдельные отчёты неисправностей.

## Increment 1: явные метрики и authority сессии

- Удалены `SurgicalHealPerformance` / `ExportPerformance`: prototype instrumentation и чтение private storage больше не применяются. Heal/Export/Topology/Geometry принимают явный MetricsSink, по умолчанию no-op. Фоновый экспорт/сравнение не сбрасывает метрики Doctor. Loader возвращает длительность; счётчики выбранной модели обновляются только после принятия результата App.
- Публичный `SurgicalHealEngine.getMemoryUsage()` считает unique backing buffers snapshots/restore/preview. Геометрия считает Morph/Index/Interleaved arrays и Mesh/Line/Points с общими backing buffers, не только длину первого subarray. Категории могут пересекаться по владению; складывать их в process RAM нельзя.
- Освобождённые pristine/reopened геометрии не показываются как retained bytes. Измерения рабочих объёмов остаются в export performance result. Текущие и сохранённые export buffers считает App, который реально их удерживает.
- AssetSession владеет borrowed root/source и serial загрузки. ExportCoordinator объединяет authority revision, busy и cached result. Stale completion не может публиковаться или разблокировать более новую операцию. Save использует тот же ticket. Существующие fingerprint/verification/revision guards остаются.
- RED: три проверки обнаружили прежний неверный счёт backing buffers, пропуск Line и отсутствие isolated sink. После исправления unit/integration **339/339 PASS**, TypeScript PASS. Production focused **9/9 PASS, 41.7 с**, включая CSP/offline Draco, PARTIAL/REGRESSION/Undo, stale preview/export и 500 001 triangles performance/fidelity.
- Один development запуск дал 8 PASS / 1 FAIL: production CSP блокирует Vite dev bootstrap, поэтому UI не появился. Это ошибка выбора режима harness; повтор сделан на свежем production build без ослабления CSP. Логи обоих запусков сохранены.

## Increment 4: журналы и служебная полоса

- Системный журнал включён по умолчанию: значок жука справа вверху, F8, дублирующий вход из нижней полосы. Просмотр по уровням, пауза, подробные записи, сохранение JSONL и очистка. Настройки записи сохраняются локально. Операции import/file read, analysis/topology, worker preview/measure, repair/Undo, export/save, rig changes/fitting и диагностические отчёты имеют явные события. Глобальные JS ошибки и rejected promises тоже записываются. Console и прототипы не подменяются.
- JSONL: время UTC, версия, session ID, sequence, operation ID, стадия, asset UUID/имя, результат/ошибка/длительность. Контекст allowlisted; binary/geometry/texture payloads не пишутся. Полные локальные пути и распространённые bearer/token/secret поля убираются. Это best-effort обработка технического текста, не анализатор всех возможных секретов.
- Окно держит до 500 записей / 1 MiB; одна запись до 16 KiB; очередь native writer до 128 записей / 1 MiB, timeout 10 с. Потерянные/неподтверждённые disk записи видны в UI. Ошибка журнала не меняет результат ремонта. Tauri пишет через отдельную blocking task в app_log_dir: три файла по 2 MiB, фиксированные имена. Экспорт включает последние три уже существовавших stage-only startup traces. Старое startup tracing остаётся независимым от нового переключателя.
- Отчёт неисправностей отделён от системного лога. Свиток рядом с Focus сохраняет одну текущую карточку, нижняя «Логировать всё» / F9 — ERROR/WARNING/UNKNOWN и MANUAL из полного текущего списка, включая Fitness, независимо от фильтра и страницы. OK/N/A/обычные INFO не входят в bulk. Отчёт JSON содержит исходные измерения и отдельные локализованные строки, версию, модель, UUID, revision/profile/stages, место, evidence/action/repairability. Partial scan и UNKNOWN не объявляются здоровой моделью.
- Объём отчёта до 4 MiB, до 1024 индексов на location и до 32 locations на карточку. Исходные totals и omitted count явно сохранены; UI предупреждает о пропусках из-за лимита. Новая модель/scan/изменённый набор карточек отменяет stale сохранение после native диалога. Во время Compare bulk Doctor отключён. Сохранение текста никогда не снимает защиту неэкспортированного ремонта модели.
- Нижняя полоса остаётся доступна вместе с timeline, содержит текущую модель, статус записи, partial scan и общую команду отчёта. Верхний значок журнала остаётся справа вне горизонтально прокручиваемых остальных controls.
- Focused browser **6/6 PASS**; TypeScript PASS; unit/integration **362/362 PASS**. В промежуточном тесте первая карточка оказалась OK и закономерно отсутствовала в bulk; тест исправлен на реальную Warning карточку, затем намеренно включает фильтр Passed перед bulk. Контракты не ослаблены. Native rotation/invalid input/canonical JSON и startup trace проверяются отдельно без запуска окна.
