# F09 — диагностические профили

15 октября 2026. Следующий пункт после принятой владельцем 2.0.12; целевая версия 2.0.13.

В Inspector под вкладками доступен выбор семи существующих профилей: общая проверка, персонаж для ПК, мобильный персонаж, статичный объект, анимированный персонаж, механический объект, визуализация / рендер. Названия и описания переключаются с RU/EN. Активный профиль виден на всех вкладках загруженной модели; ссылка открывает оценку пригодности на Perf. Выбор сохраняется при смене модели в текущем запуске, новый запуск начинает с общей проверки.

Профиль задаёт ориентиры для треугольников, вызовов отрисовки, размеров текстур, числа влияний костей и ожиданий скелета/анимации. Это справочные бюджеты пригодности, а не гарантия требований любого конкретного движка или телефона. Профиль не исправляет и не оптимизирует модель автоматически.

`HealthEngine.reinterpretFitness` получает только сохранённые метрики. Он сохраняет технические findings по ссылке и заменяет только Fitness. Проверка числа влияний костей теперь целиком относится к Fitness, включая положительный результат: иначе один и тот же профильный критерий ошибочно попадал в разные слои при переходе между 4 и 8 допустимыми влияниями.

Переключение не запускает геометрический анализ, worker, новый scan revision, правку исходника или шаг истории. Неизвестный результат после отказа topology сохраняется. Если worker ещё работает, завершение использует последний выбранный профиль. App не меняет identity callback загрузки viewport при выборе профиля.

Single/bulk JSON содержит активный профиль на уровне scan и профиль у Fitness findings. Независимые от профиля технические findings сохраняют свои первоначальные данные, включая исходный profileId при profileDependent=false; это метаданные момента получения технического результата. Для сохраняемых карточек пригодности также доступен свиток. Смена профиля во время незавершённой выгрузки делает прежний снимок неактуальным по существующему guard.

При частичном scan профиль интерпретирует уже доступные факты; отсутствие результата topology не превращается в успешную проверку. В системный журнал записывается profile_changed с mode и revision, без бинарных данных или путей к модели.

Проверки и ограничения поставки — [QA 2.0.13](QA_F09_2_0_13.md). Принятый F08 не расширяется новым orchestration framework.
